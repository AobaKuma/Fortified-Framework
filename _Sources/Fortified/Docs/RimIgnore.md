# .rimignore — 創意工坊上傳排除

讓模組資料夾內的 `.rimignore` 在上傳 Steam 創意工坊時生效，語法與 GitHub 的 `.gitignore` 完全相同。

## 為什麼需要它

Steam 的 `SteamUGC.SetItemContent` 只能指定「一個資料夾」，無法逐檔排除；RimWorld 直接把整個模組根目錄送上去。
因此原始碼、Unity 專案、`.git`、建置產物都會被一併上傳。以本專案為例，未過濾時是 **120 MB / 2164 個檔案**，過濾後是 **2.8 MB / 203 個檔案**。

## 使用方式

1. 在模組根目錄放一個 `.rimignore`（沒有這個檔案時，上傳流程與原版完全相同，不受任何影響）。
2. 照常在模組管理頁按「上傳到創意工坊」。
3. 會先跳出預覽視窗，列出**每一個將被排除的項目、命中的規則與節省的容量**；確認後才真的上傳。

開發者模式下另有兩個除錯動作（Debug actions → Fortified）：

- `預覽 .rimignore 排除結果…` — 不上傳，純 dry-run。
- `建立 .rimignore 範本…` — 在選定的本機模組產生一份帶註解的範本（已存在時不覆寫）。

## 語法

| 寫法 | 意義 |
| --- | --- |
| `# ...` | 註解（`\#` 為字面井號） |
| `!xxx` | 反選（重新納入），後出現的規則覆蓋先出現的規則 |
| `/xxx` | 錨定於模組根目錄 |
| `xxx/` | 僅匹配目錄 |
| `*` / `?` | 任意字元／單一字元（皆不跨越 `/`） |
| `[abc]` / `[!abc]` | 字元集／排除字元集 |
| `**/xxx` | 任意深度 |
| `xxx/**` | 該目錄底下全部 |

規則採 **最後命中者勝出**。樣式中間含有 `/` 時自動視為錨定樣式，否則對任意深度的同名項目生效——與 Git 一致。

**與 Git 相同的限制**：資料夾一旦被排除，其中的內容就無法再用 `!` 重新納入。要「排除資料夾內容但保留其中幾個檔案」，必須排除內容而非資料夾本身：

```
/Docs/*
!/Docs/Manual.md
```

**與 Git 的差異**：比對不分大小寫（RimWorld 主要平台的檔案系統本來就不分），且符號連結／連結點一律跳過。

### 內建預設規則

只要模組放了 `.rimignore`，以下項目會自動排除，可用 `!` 覆寫（例如 `!.gitignore`）：

```
.rimignore  .git/  .gitignore  .gitattributes  .svn/  .hg/
.vs/  .idea/  .vscode/  Thumbs.db  desktop.ini  .DS_Store
```

FF 框架本身的 `.rimignore` 就用 `!.rimignore` 覆寫了這條預設，讓設定檔隨模組一起發佈當作現成範例。

## 實作機制

| 檔案 | 職責 |
| --- | --- |
| `RimIgnoreSpec.cs` | `RimIgnoreRule` 單行解析（glob → Regex）、`RimIgnoreSpec` 規則集與最後命中者勝出比對 |
| `RimIgnorePlan.cs` | 遞迴掃描模組資料夾、剪枝、統計保留／排除的檔案數與容量（唯讀，不碰檔案） |
| `RimIgnoreStaging.cs` | 建立暫存鏡像、硬連結／複製、清理與啟動掃除 |
| `Patch_WorkshopIgnore.cs` | Harmony 串接上傳流程 |
| `Dialog_RimIgnoreConfirm.cs` | 上傳前的排除預覽視窗 |
| `RimIgnoreDebugActions.cs` | dry-run 預覽與範本產生 |
| `RimIgnoreText.cs` | 字串取得入口與鍵名常數 |

### 本地化

所有面向使用者的文字都經 `RimIgnoreText.Get(key, fallback, args…)` 取得，行為是「有翻譯就用翻譯，沒有就用內建預設值」：

- 掃描與清理可能在語言資料尚未就緒時執行（例如啟動時的殘留掃除），直接呼叫 `Translate()` 會拿到 TRANSLATION MISSING 甚至擲出例外。
- 佔位符一律以 `string.Format` 處理，翻譯字串與內建預設值共用同一組 `{0}{1}…`，缺翻譯時不會退化成半成品文字。
- 翻譯的佔位符數量與程式不符時會回傳未格式化的樣板，而不是讓整段文字消失。

共 47 個鍵，涵蓋預覽視窗、規則解析警告、掃描警告、錯誤訊息、除錯動作訊息，以及除錯動作寫出的 `.rimignore` 範本全文（`FFF_RimIgnore_Template`）。已提供 English / 繁體中文 / 简体中文 三份。取消按鈕沿用原版的 `CancelButton` 鍵。

`[DebugAction]` 的標籤必須是編譯期常數、無法走翻譯系統，因此那兩個項目採雙語標示。

### 上傳流程

1. **`Workshop.Upload` 前置攔截** — 讀 `.rimignore`、掃描產生排除計畫、顯示預覽視窗，並回傳 `false` 中止本次呼叫。
2. **使用者確認** — 在模組資料夾底下建立 `.fff_ws_staging`，用 **NTFS 硬連結**鏡射所有保留檔案（硬連結失敗時自動退回 `File.Copy`），再以旁路旗標重新呼叫原本的 `Upload`。
3. **`ModMetaData.GetWorkshopUploadDirectory` 後置導向** — 回傳鏡像資料夾，Steam 便只看得到過濾後的內容。首次發佈時會在此同步 `About/PublishedFileId.txt`。
4. **`Dialog_WorkshopOperationInProgress` 關閉時清理** — 主執行緒先試刪一次，失敗則背景重試 10 次（每 2 秒）。

鏡像放在模組資料夾內而非系統暫存資料夾，是為了保證與來源同一個磁碟區，讓硬連結一定可用（不佔額外空間、不動到原始檔案）。此資料夾永遠被排除在鏡像之外，RimWorld 也不會將其視為模組內容。

### 防護設計

- **沒有 `.rimignore` 就完全不介入**，原版流程一個位元組都不動。
- **失敗一律中止而非放行**：讀檔、掃描、建鏡像任一步失敗都會中止上傳並跳出錯誤視窗（附「仍要完整上傳」逃生口），絕不靜默送出未過濾的內容。
- **鏡像建置採全有全無**：任一檔案鏡射失敗就清除半成品並中止，不會送出內容殘缺的版本。完成後另外驗證檔案數是否相符。
- **刪除有名稱鎖**：`DeleteStagingDirectory` 只接受以 `.fff_ws_staging` 結尾的路徑，其餘一律拒絕，這是防止誤刪模組本體的最後一道鎖。
- **掃描上限**：深度 64 層、30 萬個項目；符號連結／連結點一律跳過，避免遞迴迴圈與把外部內容拉進上傳包。
- **啟動掃除**：`RimIgnoreStartupSweep` 會在遊戲啟動時清掉所有本機模組中殘留的鏡像資料夾。
- **原始檔案永遠不被移動或刪除**，全程只做讀取與建立連結。

## 驗證

`RimIgnoreRule` / `RimIgnoreSpec` 的比對邏輯已對照真實 `git check-ignore` 行為驗證：
兩組測試樹（共 70 餘個檔案）涵蓋錨定／非錨定、`**/`、`xxx/**`、目錄限定、字元集、`\*` 轉義、行尾空白、目錄剪枝、反選覆蓋等情境，
結果與 Git 完全一致。
